## Status
Development foundations and selected UI features are committed. Studio 3 can request validated shot suggestions, keep them in an editable draft, and apply them after review. Long editorial plans now run as sequential chapter batches, carry the previous shot's pose, coverage, outfit, foot styling, camera, set and lighting context forward, and retain completed suggestions if a later batch fails. The AI may suggest and validate lens and expression choices as well as the prior camera, pose, outfit, lighting and scene controls. Completed shoot frames already support optional local Ollama image review, review of selected frames, and a reviewed correction preview before retrying missing details. GPU scheduling can now optionally hold work only when every known CUDA device reports high memory pressure; that policy is off by default and queued jobs have a manual dispatch override. It uses a current VRAM snapshot, not an estimate of a workflow's peak needs. The default Studio theme uses champagne gold and steel blue with reduced-motion-aware transitions and focus states. The shared pose library includes portrait and editorial poses and now maps every selectable body pose to a prompt and mannequin. The wardrobe catalog adds 20 layered outfit sets. Physique Studio adds shoulder, arm, and calf controls; detailed descriptors are now included by the custom Chroma, Krea 2 and Pony compilers, and numeric slider values are preserved in compiled prompts. An A/B comparison panel loads only when opened, so the regular character editor does not require its query provider just to render. The video timeline can now queue enabled clips as separate jobs through the persistent serial worker, and the queue can identify each sequence clip and its resolved duration. It still needs live video workflow validation and does not stitch completed clips into a final file. The prompt library's batch importer accepts JSON, CSV or line-based text, suggests categories and controls, flags matching labels as updates, and lets the user change destinations or skip rows before saving the draft. AI batch exports preserve stable prompt IDs, category, subcategory, label and group; reimport uses the ID to update the original wording even if the external AI changed its display label. Exports can include the entire prompt catalog or a category/subcategory selection. Imported prompts remain reviewable before they are applied to the Mongo-backed prompt catalog. Full JSON backup/restore remains available for the complete catalog.

The AI workflow capability catalog now derives source-image, text-prompt, video and LoRA indicators from each saved API graph and exposes them with workflow records. Reference-based shoot selection uses this graph metadata instead of only two hard-coded workflow styles, and prompt compilation follows the selected workflow's own style. This is a structural preflight only; a visible input does not prove successful execution. Shoot Detail now summarizes Ollama's reported missing/uncertain details across frames, selects unreviewed or flagged frames, and stores explicit 1–5 user ratings. Future planner calls can use a few bounded examples rated for the same character and workflow. Ratings are advisory: the app does not rewrite a recipe, fine-tune a model, or treat vision review as ground truth. These changes have focused unit coverage but still need frontend test/build and live Ollama/ComfyUI validation on Windows.
